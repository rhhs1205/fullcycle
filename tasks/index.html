Tasks do Gestor de Tarefas

Cinco problemas que estão no projeto de propósito. Seu trabalho é encontrar a causa e corrigir cada um, com teste, usando o Claude Code e a skill /sdd.

Como trabalhar em cada task
  1. Suba o sistema com npm run dev e reproduza o problema seguindo a descrição.
  2. Crie uma branch: git checkout -b fix/task-1 (troque pelo número da task).
  3. No painel do Claude Code, no VS Code, digite /sdd task 1 e revise a spec, o plan e as tasks antes de deixar o Claude implementar.
  4. Abra um pull request quando terminar.
Como saber que terminou
  • O problema não acontece mais quando você repete o passo a passo.
  • Existe um teste novo que falha sem a sua correção e passa com ela.
  • npm test e npm run test:e2e passam.
  • A spec, o plan e as tasks da correção estão em specs/.

Passo a passo completo: seção Mão na massa do README.md e capítulo 18 do guia de estudos.

1

Tarefa excluída continua na lista

FrontendFácil

Na tela de Tarefas, ao excluir uma tarefa, aparece o aviso "Tarefa excluída.", mas a tarefa continua na tabela. Ela só some quando a página é recarregada.

Como reproduzir

  1. Abra a tela de Tarefas.
  2. Clique na lixeira de qualquer tarefa e confirme em Excluir.
  3. Veja que a linha continua lá. Aperte F5: agora ela sumiu.
Dica: a exclusão chega na API (confira na aba Network do DevTools). Compare o que acontece na tela depois de excluir com o que acontece depois de salvar uma tarefa.

Para começar: /sdd task 1

2

"Criada em" mostra a hora errada

FrontendFácil

A coluna "Criada em" da tabela de tarefas não bate com o relógio do computador. No Brasil, a hora aparece 3 horas adiantada, e uma tarefa criada à noite pode aparecer com a data do dia seguinte.

Como reproduzir

  1. Crie uma tarefa pelo botão "Nova tarefa".
  2. Compare a hora da coluna "Criada em" com o relógio do computador.
Dica: a API guarda e devolve a data certa. Confira o campo criadaEm na resposta, pela aba Network ou pelo Swagger. O problema está em como a tela mostra essa data.

Para começar: /sdd task 2

3

Editar uma tarefa concluída faz ela voltar a pendente

FrontendMédio

Ao editar uma tarefa que já está concluída, por exemplo só para mudar o título, ela volta a ficar pendente depois de salvar.

Como reproduzir

  1. Marque uma tarefa como concluída na tabela.
  2. Clique no lápis dessa tarefa. Repare na caixa "Concluída" do formulário.
  3. Mude só o título e salve. A tarefa volta para o grupo das pendentes.
Dica: olhe com que valores o formulário de edição começa preenchido e compare campo a campo com a tarefa que você abriu.

Para começar: /sdd task 3

4

Nome de categoria comprido derruba a API

Frontend e APIMédio

Criar uma categoria com um nome de 61 a 80 caracteres mostra "A API encontrou um problema. Tente de novo em instantes." e o terminal da API mostra um erro vindo do banco. Com até 60 caracteres, funciona.

Como reproduzir

  1. Abra a tela de Categorias e clique em "Nova categoria".
  2. Digite um nome com uns 70 caracteres e salve.
  3. Repita pelo Swagger (http://localhost:3000/docs, rota POST /categorias) e veja o status da resposta.
Dica: procure o limite de tamanho do nome em cada camada: na tela, na validação da API e na tabela do banco. Lembre que dado inválido deveria receber 400, não 500.

Para começar: /sdd task 4

5

"Pendentes por prioridade" conta tarefas concluídas

APIMédio

No Dashboard, a soma do painel "Pendentes por prioridade" passa do número do card "Pendentes". Concluir uma tarefa não diminui o número da prioridade dela.

Como reproduzir

  1. Abra o Dashboard e some os três números de "Pendentes por prioridade". Compare com o card "Pendentes".
  2. Conclua uma tarefa de prioridade alta na tela de Tarefas.
  3. Volte ao Dashboard e clique em "Atualizar": o número de "Alta" continua igual.
Dica: os números chegam prontos da API, no GET /dashboard/resumo. Veja como a consulta que agrupa por prioridade escolhe quais tarefas entram na conta.

Para começar: /sdd task 5
